دليل أدوار وصفحات الـ Organization

هذه الوثيقة تشرح الأدوار داخل الـ Organization، ما الذي يستطيع كل Role فعله، وما هي الصفحات المتاحة له داخل النظام.

Provider Organization Consumer Organization Hybrid Organization Platform Administrator

1. المفهوم العام

النظام يفرق بين نوعين أساسيين من المنظمات:

  • Provider Organization: منظمة تنشر Models، تراجع Versions، تعتمد الإصدارات، وتتابع الأرباح والـ Production readiness.
  • Consumer Organization: منظمة تستهلك Marketplace Models من خلال Projects و API Keys وتدير رصيد Credits.
  • Hybrid Organization: تجمع بين Provider و Consumer في نفس الـ workspace، مع فصل واضح بين Credits و Earnings.
مهم: الـ Provider Organization لا يجب أن يظهر له Consumer Balance كجزء أساسي من تجربته. Provider-only يستخدم Provider Earnings فقط. Consumer Credits تظهر فقط في Consumer أو Hybrid.

2. الفرق بين Organization Roles و Platform Administrator

النوع المعنى نطاق الصلاحية
Organization Owner أعلى Role داخل منظمة معينة. يدير أعضاء المنظمة، الإعدادات، الحوكمة، الإصدارات، والماليات الخاصة بنفس المنظمة فقط.
Organization Maintainer Role تشغيلي موثوق داخل المنظمة. يراجع Versions، يدير أعضاء، ويوافق أو يرفض الإصدارات حسب نوع المنظمة.
Platform Administrator ليس Role داخل Organization. صلاحية على مستوى المنصة بالكامل: المستخدمين، الأسعار العامة، البنية التحتية، إعدادات النظام، الدعم، والرقابة العامة.

3. Provider Organization Roles

Provider Organization مبنية حول نشر Models بشكل حوكمي: Contributor يرفع، Owner/Maintainer يراجعوا ويقرروا، Viewer يراقب فقط.

Role ماذا يفعل؟ ماذا لا يفعل؟
Owner
  • يدير أعضاء المنظمة وأدوارهم.
  • يراجع Versions و Deployments.
  • يعتمد أو يرفض الإصدارات.
  • يفرض قرارات الحوكمة.
  • يرى Provider Finance والأرباح.
  • يدير إعدادات المنظمة.
 ليس Platform Administrator ولا يدير إعدادات المنصة العامة إلا إذا كان لديه Admin role منفصل.
Maintainer
  • يراجع Artifacts و Preprocess و Postprocess.
  • يراجع Test Cases وخطة الاختبار.
  • يعتمد أو يرفض Version.
  • يدير أعضاء المنظمة حسب السياسة الحالية.
  • يدير Production readiness.
 لا يدير Billing أو Settings الحساسة إذا كانت مقصورة على Owner.
Contributor
  • يرفع Models و Versions.
  • يرفع Model artifact و Scaler و Preprocess و Postprocess.
  • يضيف Test Cases.
  • يتابع حالة الـ Review الخاصة بما تم رفعه.
 لا يعتمد Versions، لا يرفض Versions، لا يطلع إصدار إلى Production، ولا يدير أعضاء.
Viewer
  • يرى Model registry.
  • يرى Versions وحالة الـ Review.
  • يرى History و Analytics المسموح بها قراءة فقط.
 لا يرفع، لا يعدل، لا يعتمد، لا يرفض، ولا يدير أي شيء.

4. Consumer Organization Roles

Consumer Organization مبنية حول استخدام Marketplace Models من خلال Projects و API Keys ورصيد Credits.

Role ماذا يفعل؟ الصفحات الأساسية
Owner يدير الأعضاء، المشاريع، API Keys، الرصيد، الإعدادات، ومراقبة الاستخدام. Overview, Members, Projects, Project Details, Billing, Settings
Maintainer يدير Projects و API Keys و usage operations و member access. Overview, Members, Projects, Project Details
Contributor يعمل على تكاملات المشاريع و API Keys حسب صلاحيات المنظمة. Overview, Projects, Project Details
Viewer يراقب Projects و Usage بدون تعديل. Overview, Projects, Usage sections

5. صفحات الـ Organization الموجودة في النظام

الصفحة Route الغرض مين يدخلها؟
Overview /orgs/[orgSlug]/overview ملخص المنظمة، نوعها، عدد الأعضاء، عدد المشاريع أو الموديلات، workflows حسب النوع. كل الأدوار داخل المنظمة.
Members /orgs/[orgSlug]/members إدارة الأعضاء، تغيير الأدوار، دعوة أو إزالة أعضاء، وتوضيح الفرق بين Organization RBAC و Platform Admin. Owner و Maintainer.
Billing / Provider Finance /orgs/[orgSlug]/billing Consumer: رصيد Credits و Top-up و Ledger. Provider: أرباح Provider و Earnings Ledger فقط. Hybrid: فصل بين Consumer Credits و Provider Earnings. Owner غالبًا. Provider finance لصاحب القرار المالي.
Settings /orgs/[orgSlug]/settings بيانات المنظمة، الاسم، الوصف، الشعار، وإعدادات الهوية. Owner فقط أو حسب سياسة الإعدادات.
Projects /orgs/[orgSlug]/projects قائمة مشاريع Consumer organization، إنشاء مشاريع، متابعة project workspaces. Consumer/Hybrid فقط حسب الدور.
Project Details /orgs/[orgSlug]/projects/[projectId] إدارة API Keys، رؤية usage، logs، وربط كل تطبيق أو environment بمفاتيح منفصلة. Consumer/Hybrid حسب صلاحيات Projects و API Keys.
Provider Models /orgs/[orgSlug]/models Model registry الخاص بالمنظمة، حالة الإصدارات، readiness، live deployments، وروابط Analytics و Versions و Upload. Provider/Hybrid: كل الأدوار حسب مستوى القراءة أو العمل.
Upload Model /orgs/[orgSlug]/models/upload رفع Model جديد أو Version جديد داخل المنظمة نفسها، وليس كـ personal upload. Owner, Maintainer, Contributor.
Model Review Page /orgs/[orgSlug]/models/[modelId] صفحة Pull Request style: Artifact preview، Test plan، Review decision، Hard history، Versions list. كل أدوار Provider تقرأ، Owner/Maintainer يقرروا.
Provider Analytics /orgs/[orgSlug]/models/analytics Dashboard لصاحب القرار: revenue، pending reviews، production، release risk، verified models، ومساهمة الأعضاء. Owner و Maintainer.
Versions Control /orgs/[orgSlug]/models/versions صفحة مركزية لكل Versions في المنظمة: approve/decline، production status، uploader، reviewer، build status. Owner و Maintainer.

7. Workflow الخاص بالـ Provider Organization

1. Submit Work

Contributor أو Maintainer أو Owner يرفع Model أو Version من صفحة Upload Model.

/orgs/[orgSlug]/models/upload

2. Review Version

Owner أو Maintainer يفتح Review page، يراجع artifacts و preprocess و postprocess و test cases.

/orgs/[orgSlug]/models/[modelId]

3. Approve or Decline

لو الإصدار جاهز، يتم اعتماده ويبدأ build. لو غير جاهز، يتم رفضه مع comment في history.

/orgs/[orgSlug]/models/versions

4. Production + Marketplace

الإصدارات المعتمدة يمكن أن تصل إلى Production وتظهر Verified في Marketplace حسب readiness.

/explore

8. ملاحظات تصميم ومنطق

  • Provider-only لا يظهر له Top-up ولا Consumer Balance.
  • Provider Finance يعرض الأرباح والـ provider ledger فقط.
  • Consumer Billing يعرض credits و top-up و project spend.
  • Hybrid يعرض الاثنين ولكن بفصل واضح.
  • Versions Control و Analytics صفحات Governance، لذلك Owner/Maintainer فقط.
  • Upload متاح للـ Contributor لأنه يقدم العمل لكنه لا يقرر Production.
  • Hard history تحفظ كل submission و test case و approval و decline.
  • Platform Administrator منفصل تمامًا عن Organization roles.
